Hello everyone! 👋

Welcome to the **Sovereign AI Stack** community space. Whether you are a security researcher, a systems engineer, an ML engineer, or a compliance professional, we are thrilled to have you here.

We started this project to explore what it takes to build a completely private, offline-first RAG pipeline that doesn't compromise on security. With the launch of our **v2.0 Strategic Maturation and Refactor**, we are transitioning from a prototype into a **hardware-rooted reference architecture for zero-trust AI governance**.

To achieve this, we have organized our development around **5 Core Pillars**. We have opened high-priority issues for each of these pillars and are inviting the community to collaborate, self-assign, and build with us:

| Pillar | Focus Area | Recommended Skills | GitHub Issue Link |
| :--- | :--- | :--- | :--- |
| 🔒 **1. Attestation Isolation** | Move attestation checks into isolated secure enclaves (SGX/SEV) | Rust, gRPC, Enclave Security | [#1: Refactor AttestationVerifier into Enclave Microservice](https://github.com/anandkrshnn/sovereign-ai-stack/issues) |

| 📥 **3. Async Audit Ledger** | Build out-of-band audit logging via task queues to WORM storage | Python, Asyncio, Cloud Storage | [#3: Build Asynchronous Append-Only Audit Ledger](https://github.com/anandkrshnn/sovereign-ai-stack/issues) |
| 🌐 **4. Ontology Policy Engine** | Shift policy verification to rich OWL/RDF ontology models | Semantic Web, RDFlib, Z3 Solver | [#4: Upgrade Policy Verifier to Ontology-Driven Model](https://github.com/anandkrshnn/sovereign-ai-stack/issues) |

### 🗺️ How to Get Started

1.  **Read the Onboarding Guide**: We have compiled a detailed developer setup, directory mapping, and local verification flow in [CONTRIBUTOR_ONBOARDING_v2.0.md](https://github.com/anandkrshnn/sovereign-ai-stack/blob/main/docs/CONTRIBUTOR_ONBOARDING_v2.0.md).
2.  **Pick an Issue**: Head over to the [Sovereign AI Stack Issues](https://github.com/anandkrshnn/sovereign-ai-stack/issues) page, find the pillar that fits your expertise, and leave a comment to self-assign.
3.  **Submit a Draft PR**: We encourage opening Draft PRs early so we can collaborate on the implementation design.

### 🛡️ Technical Rigour & Principles
In line with our [CONTRIBUTING.md](https://github.com/anandkrshnn/sovereign-ai-stack/blob/main/CONTRIBUTING.md), we value technical accuracy, safety, and intellectual honesty. If you find a security vulnerability, please report it privately to `ananda.krishnan@hotmail.com`. For all other architectural reviews or improvements, open a discussion thread right here!

Let's build a truly sovereign, provable AI infrastructure.
